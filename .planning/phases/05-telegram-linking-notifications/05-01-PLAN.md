<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram client → link endpoint | Untrusted payload/token enters privileged linking flow |
| Edge Function → Postgres | Service role can mutate sensitive linkage tables |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | S | link token consume | mitigate | Hash tokens at rest; compare hash only; reject unknown token. |
| T-05-02 | T | telegram account binding | mitigate | Bind consume contract to token-owned `profile_id`; no caller-supplied profile override. |
| T-05-03 | R | link completion events | mitigate | Insert audit log entry for consume success/failure attempts. |
| T-05-04 | I | token leakage | mitigate | Enforce short expiry and single-use `consumed_at` guard. |
| T-05-05 | D | brute force token attempts | mitigate | Return generic 4xx; add attempt throttling hooks in function. |
| T-05-06 | E | service role misuse | mitigate | Keep service key only in function env and restrict mutation path to consume contract. |
</threat_model>
