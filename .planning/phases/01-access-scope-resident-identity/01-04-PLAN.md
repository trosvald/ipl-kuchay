<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| resident form → profile update RPC | User-submitted profile fields cross into privileged profile storage |
| resident form → notification preferences table | Preference writes must remain account-owned and category-scoped |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | T | Resident settings payload | mitigate | Validate only `display_name`, `phone`, and category preference fields; do not expose `role`, `is_active`, or `full_name` as writable inputs. |
| T-04-02 | I | Read-only identity display | mitigate | Keep protected identity data visible but clearly marked read-only so residents understand scope without confusing it for editable state. |
| T-04-03 | E | Preference writes | mitigate | Use authenticated ownership queries/RPCs from Plan 01 so residents can update only their own preference rows. |
</threat_model>
