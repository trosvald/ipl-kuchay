<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser resident → Supabase tables/storage | Resident input and download requests are untrusted and must be scoped to published content + self-owned RSVP rows |
| Browser admin/super_admin → Supabase tables/storage | Content lifecycle changes come from browser clients and must still be policy-enforced |
| Supabase storage → resident attachment access | Resident file access must follow announcement visibility, not public bucket exposure |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | E | announcement/event write path | mitigate | Restrict `announcements` and `events` write policies to `admin`/`super_admin`; do not reuse broad treasurer finance helpers for content management |
| T-04-02 | I | resident announcement/event reads | mitigate | Resident `SELECT` policies require published/visible rows only; no draft rows are loaded then filtered client-side |
| T-04-03 | T | RSVP mutation path | mitigate | `event_attendees` unique `(event_id, profile_id)` plus `(select auth.uid()) = profile_id` `WITH CHECK` and event-start cutoff |
| T-04-04 | I | announcement attachments | mitigate | Use resident-authenticated storage access tied to resident-visible announcements; no public bucket or browser-held secret keys |
</threat_model>
