<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| treasurer/admin browser → report-output Edge Functions | Untrusted UI input chooses which finance artifacts to generate and download. |
| Edge Functions → private storage bucket | Privileged service-role upload and signed URL creation can leak sensitive receipt files if authorization is wrong. |
| `public.reports` metadata → resident receipt visibility | Incorrect `kavling_id` or metadata linkage could expose another resident's receipt history. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-13 | S | `generate-report-output` request payload | mitigate | Validate UUID inputs and require `treasurer`, `admin`, or `super_admin` before any data load or upload. |
| T-03-14 | I | `report-outputs` private files | mitigate | Store artifacts only in a private bucket and deliver access exclusively through a 300-second signed URL function per D-05. |
| T-03-15 | T | `public.reports` receipt metadata | mitigate | Persist `kavling_id`, `invoice_id`, and `payment_id` together so receipt rows can be RLS-checked against the correct resident scope. |
| T-03-16 | R | finance report/receipt downloads | mitigate | Audit finance signed-URL openings with actor, report id, and expiry metadata in `public.audit_logs`. |
| T-03-17 | E | service-role upload helper | mitigate | Keep service-role usage inside Edge Functions only; browser code calls invoke wrappers and never handles storage secrets directly. |
</threat_model>
