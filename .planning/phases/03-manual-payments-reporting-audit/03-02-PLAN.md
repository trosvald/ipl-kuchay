<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| resident browser → payment submission APIs/storage | Untrusted user input and files cross into privileged validation and storage workflows. |
| treasurer/admin browser → review RPC + proof signed URL function | Privileged review actions and file access are triggered from client-side controls. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | T | `PaymentSubmissionForm` payload/file inputs | mitigate | Keep schema/file validations enforced before invoke/upload and block ineligible invoice states. |
| T-03-06 | I | `ProofPreviewButton` file access path | mitigate | Use signed URL function only; never expose storage public URLs or raw paths as clickable links. |
| T-03-07 | R | Admin review decisions in UI | mitigate | Surface RPC errors/success deterministically and rely on backend audit trail for final decision evidence. |
| T-03-08 | S | Role misuse in admin review surface | mitigate | Keep access behind existing admin-like route guards and backend authorization checks in RPC/Edge functions. |
</threat_model>
